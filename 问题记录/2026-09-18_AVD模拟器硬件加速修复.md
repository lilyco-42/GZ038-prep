# 2026-09-18 Android 模拟器（AVD）无法启动修复记录

## 现象

- Android Studio 运行 Pixel_API_26（x86, Android 8.0）模拟器，进程立即退出
- Event Log：`Emulator: ERROR: x86 emulation currently requires hardware acceleration!`
- `Emulator: Process finished with exit code 1`

## 根因（三层）

1. **硬件加速不可用**
   - `emulator -accel-check` 输出：`HAXM is not installed, but Windows Hypervisor Platform is available`，accel=0
   - 启用 Windows 功能 `HypervisorPlatform`（状态变 Enabled）并重启后，`HypervisorPresent` 仍为 **False**
   - 系统提示 `Restart Required: Possible` 悬挂——**还原卡阻止了 Windows hypervisor 实际加载**
   - CPU（i7-12700）BIOS 虚拟化已开启（Firmware: Yes），硬件无问题

2. **系统镜像缺失**
   - SDK 的 `system-images\` 目录整个不存在（从未安装，且备份时也没有）
   - AVD 配置指向 `google_apis_playstore`，但无对应镜像文件

3. **还原卡持续还原 C 盘**
   - 重启后 `gh-cli`、`Doubao\chats`、下载的镜像均被还原清空
   - 新增到 C 盘的内容（驱动、镜像、数据）重启后可能再次丢失

## 解决方案（最终生效）

| 步骤 | 操作 | 结果 |
|---|---|---|
| 1 | 安装 **Intel HAXM 7.8.0**（`haxm-7.8.0-setup.exe /S`，走 VT-x 直驱，不依赖 Windows hypervisor） | `sc query intelhaxm` = RUNNING；accel-check：`HAXM version 7.8.0 is installed and usable` |
| 2 | 用 sdkmanager 重新下载镜像：`system-images;android-26;google_apis;x86` | 下载解压完成，system.img 就位 |
| 3 | 修改 AVD `config.ini`：`image.sysdir.1` 由 `google_apis_playstore` 改为 `google_apis` | 配置正确 |
| 4 | 启动验证 | `boot_completed=1`；`adb devices` = emulator-5554 device |
| 5 | 安装国赛1 远程监控 APK 验证 | `adb install` Success，应用界面正常渲染 |

## 关键结论

- **HAXM 方案在本机有效**（绕过被还原卡阻止的 WHPX/hypervisor）
- 下载源：`https://github.com/intel/haxm/releases/download/v7.8.0/haxm-windows_v7_8_0.zip`（走 ghproxy 镜像）
- 镜像包：`system-images;android-26;google_apis;x86`（约 600MB，dl.google.com 可直连）

## 注意（还原卡环境）

- 每次重启后需检查：HAXM 驱动是否被还原（`sc query intelhaxm`）、镜像是否还在
- 建议：将 Android SDK + AVD 迁移到 D 盘（U 盘，还原卡不还原），或扩展一键恢复脚本自动重装 HAXM + 重下镜像
- 备份位置：`D:\备份_还原前\`（chats/gradle/gh-cli/android-sdk + 一键恢复.bat/ps1）
